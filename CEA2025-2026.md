## First plugin — MeshBooleanPlugin (Nov 2025 – Jan 2026)

### Context

The MeshBooleanPlugin performs boolean operations (union, intersection, difference) between
two surface meshes and imports the result directly into SALOME. It integrates 6 C++ engines:
CGAL, CORK, MCUT, libigl, IRMB and VTK.

When I took over the plugin in November 2025, it had several limitations:
- No way to cancel a running computation — the user had to kill SALOME entirely
- Algorithm logic and GUI code were mixed together — no Python API, no automated tests
- No integration with SALOME's dump study system
- Intermediate temporary files were never cleaned up

### Contributions

#### Cancel button — a cross-platform challenge

My first task was implementing a mechanism to cancel a running computation.

**First attempt:** Python's `multiprocessing` module. It worked on Linux but failed on Windows,
where process management works fundamentally differently.

**Solution:** combining `subprocess` (launches the algorithm as an external process) with
PyQt's `QThread` (monitors the process asynchronously without freezing the GUI).
When the user clicks Cancel, a Qt signal terminates the process cleanly,
with the same behavior on Linux and Windows.

**Git workflow:** during the review, a conflict arose because the SALOME team had renamed
all imports to `salome.kernel`. I resolved it with an interactive rebase.

#### Python API & GUI decoupling

SALOME can be used through its GUI or through Python scripts. The plugin had no standalone API,
which made automation and testing impossible.

I extracted all algorithm logic into an independent module, `mesh_boolean_api.py`.
The PyQt GUI became a thin wrapper calling this API, with no business logic of its own.

This enabled:
- Full command-line execution without opening SALOME
- Automated testing with Python's `unittest` module — 15 subtests covering
  5 engines × 3 operations, with results validated to a tolerance of 5×10⁻⁴
- A code quality pass with Pylint across the entire codebase

**Build system cleanup:** removed fragile `sed` and `echo` injections from the Makefile
that patched the generated `MyPlugDialog_ui.py` at build time:

```bash
# Removed legacy hacks:
sed -i '$ d' MyPlugDialog_ui.py
echo "from qwt import QwtPlot" >> MyPlugDialog_ui.py
```

They were replaced by a proper import structure, making the build cleaner and
reproducible across environments.

**UI cleanup:** removed obsolete charts from the dialog box, resulting in a simpler interface.

> Merged as part of [Complete dump study on boolean operations #26](https://github.com/SalomePlatform/meshbooleanplugin/pull/26)

---

#### Temporary files & error handling

Each boolean operation generated intermediate files (`.off`, `.stl`, `.obj`) in `/tmp`
that were never deleted and accumulated indefinitely.

I centralized their handling in a dedicated temporary directory managed by a Python
context manager, guaranteeing cleanup in every case: success, cancellation, or runtime error.

I also fixed an inconsistent UI state after a computation error: the error signal only
displayed a message, leaving the interface locked in a "computing" state. The handler now
stops the worker thread, resets the computing state, the cursor and the buttons,
then reports the error.

**Known issue documented:** identified and documented a bug in the loading of GEOM `.hdf`
files, which currently prevents boolean operations on this format.

---

#### Dump study integration

SALOME's dump study records all GUI actions as a replayable Python script.
Without specific integration, the plugin's intermediate exports were recorded verbatim,
producing broken scripts that referenced temporary files which no longer existed.

**Solution:** suspend recording during intermediate export steps, then inject clean API calls
directly into the dump. Any session using the plugin now produces a readable, self-contained
Python script that can be replayed or modified without manual interaction.

> PR: [Complete dump study on boolean operations #26](https://github.com/SalomePlatform/meshbooleanplugin/pull/26) — merged

---

#### Debug & verbose mode

Added a verbose mode controlled by the environment variables `SALOME_VERBOSE=1`
or `DEBUG_PLUGIN=1`. When active, the plugin logs algorithm calls, intermediate file paths
and process return codes. It stays silent in production.

## Second plugin — PolyMeshPlugin (Feb 2026 – Apr 2026)

### Context

The PolyMeshPlugin converts any closed mesh into a polyhedral mesh using three C++ algorithms:
Polydual and cfMesh (both based on OpenFOAM), and Geogram (Voronoi diagrams via Vorpalite).

The plugin had been started by an intern during a 5-month internship. The prototype worked
under certain conditions but had several blocking issues:
- `pexpect` / `wexpect` for process communication — unstable on Windows and requiring
  a post-install script
- GUI freezing after computation, with no visual feedback
- No error handling — silent failures
- A fragile Python parser for the `.ovm` format in the Geogram pipeline

### Contributions

#### Cross-platform refactoring

Replaced `pexpect` / `wexpect` with Python's standard `subprocess` module,
the approach already proven on MeshBooleanPlugin: no external dependency and identical
behavior on Linux and Windows.

Keeping the real-time progress bar with `subprocess` required reading the process output
character by character into a buffer, flushed at each space or newline and parsed on the fly
to update the PyQt progress bar at each algorithm stage.

Debug output was standardized with `verbose` and `debug_plugin` modes,
consistent with MeshBooleanPlugin.

---

#### Error handling & UX

- **Post-computation loading dialog:** shown once the progress bar reaches 100%, with a
  busy cursor, preventing interaction while the `.med` file loads into SALOME's Object Browser.
- **Empty mesh detection (cfMesh):** a `checkMeshNotEmpty` function reads the algorithm's output
  and checks the number of generated points. If it is zero, a clear message tells the user to
  adjust the maximum cell size, and the process stops before useless conversion steps.
- **Partial group transfer:** a warning replaces the previous silent failure. The mesh is still
  loaded, and the user is advised to retry with different parameters or create the missing groups.
- **Faster startup:** replaced the `paraview.simple` import with a `pvbatch` call,
  removing several seconds of delay when opening the SMESH module and fixing recurring
  `cftime` errors.

---

#### Session management & UI automation

- **Parameter persistence:** plugin parameters are kept within a SALOME session
  and reset to their defaults in a new session.
- **Dynamic naming:** renaming a mesh in the Object Browser is now reflected
  when the plugin dialog is reopened.
- **Auto-selection:** a mesh selected in the Object Browser before opening the plugin
  is automatically pre-selected in the dialog.

---

#### Geogram pipeline overhaul — `geogram2med`

The original Geogram pipeline produced an `.ovm` (OpenVolumeMesh) text file,
parsed in Python before being imported into SALOME. It was slow, hard to debug
and sensitive to changes between Geogram versions.

I developed a dedicated C++ executable, `geogram2med`, built with CMake on top of two libraries:
- **Geogram** — reads the native binary `.geogram` file produced by Vorpalite
- **MEDCoupling** — rebuilds the polyhedra and exports them directly to `.med`

How it works:
1. Load the `.geogram` file with the Geogram library
2. Extract node coordinates into a MEDCoupling `DataArrayDouble`
3. Group 2D facets by their `cell_id` attribute (set when `poly:generate_ids=true` is enabled in Vorpalite)
4. Rebuild 3D polyhedra, faces separated by `-1`, following MEDCoupling's `NORM_POLYHED` convention
5. Compute the 2D skin of the volume with `computeSkin()`
6. Export the `.med` file with the volume mesh, the surface mesh and their groups

The Python layer now simply imports the `.med` file natively. The fragile parser is gone,
and the pipeline is faster and easier to maintain.

> PolyMeshPlugin is hosted in an internal CEA/EDF repository.
> These changes will be available in the next public SALOME release.
