## Semester 1 — MeshBooleanPlugin (Nov 2025 – Jan 2026)

### Context

The MeshBooleanPlugin performs boolean operations (union, intersection, difference) between
two surface meshes and imports the result directly into SALOME. It integrates 6 C++ algorithms:
CGAL, CORK, MCUT, libigl, IRMB and VTK.

When I took over the plugin in November 2025, it had several limitations:
- No way to cancel a running computation — the user had to kill SALOME entirely
- Algorithm logic and GUI code were mixed together — no Python API, no automated tests
- No integration with SALOME's dump study system
- Intermediate temporary files were never cleaned up

### Contributions

#### Cancel button — cross-platform challenge

My first task was implementing a computation cancellation mechanism.

**First attempt:** Python's `multiprocessing` module. Worked on Linux, failed on Windows —
process management differs fundamentally between the two systems.

**Solution:** Combined `subprocess` (launches the algorithm as an external process) with
PyQt's `QThread` (monitors the process asynchronously without freezing the GUI).
When the user clicks Cancel, a Qt signal terminates the process cleanly.
Same behavior on Linux and Windows.

**Git workflow:** During the PR review, a conflict arose — the SALOME team had renamed
all imports to `salome.kernel`. Resolved with an interactive rebase.

> PR: [Add Cancel Button #22](https://github.com/SalomePlatform/meshbooleanplugin/pull/22)

---

#### Python API & GUI decoupling

SALOME can be used via GUI or Python scripts. The plugin had no standalone API,
making automation and testing impossible.

I extracted all algorithm logic into an independent module `mesh_boolean_api.py`.
The PyQt GUI became a simple wrapper calling this API, with no business logic of its own.

This enabled:
- Full command-line execution without opening SALOME
- Automated testing with Python's `unittest` module — 15 subtests covering
  5 algorithms × 3 operations, precision validated at 5×10⁻⁴
- Code quality pass with Pylint across the entire codebase

**Build system cleanup:** Removed manual hacks from the UI compilation process in the Makefile,
including fragile `sed` and `echo` injections that were patching the generated `MyPlugDialog_ui.py`
at build time:

```bash
# Removed legacy hacks:
sed -i '$ d' MyPlugDialog_ui.py
echo "from qwt import QwtPlot" >> MyPlugDialog_ui.py
```

These were replaced by a proper import structure, making the build process cleaner and
reproducible across environments.

**UI cleanup:** Removed obsolete graphics and charts from the boolean operations dialog box
that were no longer useful, resulting in a cleaner interface.

---

#### Temporary file management

Each boolean operation generated intermediate files (`.off`, `.stl`, `.obj`) stored in `/tmp`
and never deleted, accumulating indefinitely.

Implemented a centralized cleanup using a Python context manager (`with / try`),
guaranteeing deletion in all cases — success, cancellation, or runtime error.

**Error handling fix:** Identified and fixed an inconsistent UI state when a computation error
occurred. The previous signal connection only displayed the error message but failed to reset
the interface, leaving the application in a locked "computing" state:

```python
# Previous broken connection:
self.worker.error.connect(lambda e: self.error_popup("Computation error", e))

# Fixed connection — full UI reset on error:
self.worker.error.connect(lambda e: [
    self.thread.quit(),
    setattr(self, 'computing', False),
    self.restoreCursor(),
    self.updateButton(),
    self.error_popup("Computation error", e)
])
```

**Known issue documented:** Identified and documented a bug regarding the loading of GEOM
`.hdf` files, which currently prevents boolean operations on this specific format.

---

#### Dump study integration

SALOME's dump study records all GUI actions as a replayable Python script.
Without specific integration, the plugin's intermediate file exports were captured verbatim,
producing broken scripts with references to temporary files that no longer existed.

Solution: suspend recording during intermediate export steps, then inject clean API calls
directly into the dump. Any session using the plugin now produces a readable, self-contained
Python script that can be replayed or modified without manual interaction.

---

#### Debug & verbose mode

Added a conditional verbose mode controlled by environment variables `SALOME_VERBOSE=1`
or `DEBUG_PLUGIN=1`. When active, the plugin logs detailed information about algorithm calls,
intermediate file paths and process return codes. Silent in production.

## Semester 2 — PolyMeshPlugin (Feb 2026 – Apr 2026)

### Context

The PolyMeshPlugin converts any closed mesh into a polyhedral mesh using three C++ algorithms:
Polydual, cfMesh (both based on OpenFOAM) and Geogram (Voronoi diagrams via Vorpalite).

The plugin had been started by a 5-month intern. The prototype worked conditionally but had
several blocking issues:
- `pexpect` / `wexpect` for process communication — unstable on Windows, required
  a post-install script
- GUI froze after computation with no visual feedback
- No error handling — silent failures
- Geogram pipeline used a fragile ~200-line Python parser for the `.ovm` format

### Contributions

#### Cross-platform refactoring

Replaced `pexpect` / `wexpect` with Python's standard `subprocess` module —
the same approach proven on MeshBooleanPlugin. No external dependency, identical
behavior on Linux and Windows.

Reproducing the real-time progress bar with `subprocess` required reading the process
output character by character into a buffer, flushed at each space or newline,
parsed in real time to update the PyQt progress bar at each algorithm stage.

**Debug & logging:** Standardized communication between the plugin and the terminal
with `verbose` and `debug_plugin` modes, consistent with the approach used on MeshBooleanPlugin.

---

#### Error handling & UX

- **Post-computation loading box:** added after the progress bar reaches 100%,
  preventing the user from interacting with the interface while the `.med` file loads
  into SALOME's object browser. A busy cursor is also displayed to indicate the application
  is still active.
- **Empty mesh detection (cfMesh):** implemented a `checkMeshNotEmpty` function in `pmpAPI`
  that reads the algorithm's output file and checks the generated point count after computation.
  If zero, a clear warning message guides the user to adjust the Max cell size parameter,
  stopping the process before useless conversion steps.
- **Partial group transfer:** warning displayed instead of silent failure — the mesh is still
  loaded but the user is advised to retry with different parameters or create missing groups manually.
- **Startup optimization:** replaced `paraview.simple` import with `pvbatch`,
  eliminating several seconds of delay when opening the SMESH module and resolving
  recurrent `cftime` errors.

---

#### Session management & UI automation

- **Parameter persistence:** plugin parameters are saved within the same SALOME session
  and reset to default values when a new session is launched.
- **Dynamic naming:** fixed an issue where renaming a mesh in the Object Browser was not
  reflected when reopening the plugin dialog.
- **Auto-selection:** if a mesh is selected in the Object Browser before opening the plugin,
  it is automatically pre-selected in the dialog, avoiding unnecessary clicks.

---

#### Geogram pipeline overhaul — geogram2med

The original Geogram pipeline produced a `.ovm` (OpenVolumeMesh) text file,
parsed by ~200 lines of fragile Python before import into SALOME.
Slow, hard to debug, sensitive to Geogram version changes.

I developed a dedicated C++ executable `geogram2med`, compiled with CMake,
using two libraries:
- **Geogram** — reads the native `.geogram` binary produced by Vorpalite
- **MEDCoupling** — reconstructs the polyhedra and exports directly to `.med`

How it works:
1. Load the `.geogram` file via the Geogram library
2. Extract node coordinates into a MEDCoupling `DataArrayDouble`
3. Group 2D facets by their `cell_id` attribute (set when `poly:generate_ids=true` is active in Vorpalite)
4. Reconstruct 3D polyhedra separated by `-1`, following MEDCoupling's `NORM_POLYHED` convention
5. Compute the 2D skin of the volume via `computeSkin()`
6. Export the `.med` file with volumetric mesh, surface mesh and associated groups

The Python layer now simply imports the `.med` file natively.
Result: ~200 lines of fragile Python removed, faster and more maintainable pipeline.

**Group transfer fix:** After the architectural overhaul, a freezing issue occurred when
transferring 2D boundary groups back onto the imported 3D volume. Investigation revealed
that Geogram occasionally generated polyhedra with corrupted topology (inverted cells),
causing SALOME's `CutListOfGroups` boolean operation to freeze.

Fix: replaced the heavy boolean-based group transfer with a direct node mapping approach —
targeting the first node of the first face of each separated group, bypassing complex
topology checks entirely. Group transfer went from several minutes (with freezing) to
a fraction of a second.
